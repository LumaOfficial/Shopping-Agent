Data on this device

Reading local data…

Everything above lives in this browser profile. Nothing is uploaded, sold or shared, and card details are never read — unless you seal a backup and keep it somewhere yourself, which is the one thing that leaves this device and is covered next.

Backup and recovery

A wiped, reset, lost or replacement device gets everything back from one sealed code — your account and balance, saved and verified codes, price history, settings and tour. The code is locked on this device with AES-256-GCM under a recovery key of 160 random bits stretched by 600,000 rounds of PBKDF2-SHA-256. Neither we nor the host that stores it can open it: with the key it opens, without it the file is noise.

Checking…

Keep the recovery key somewhere that survives this device — written down, in a password manager, or on paper with your passport. Losing the device and the key together cannot be undone, by us or by anyone else. Provider credentials under Developer are never included, so a restored device asks for those again.

Keeping the sealed code off this device

An address you control that keeps the sealed code. After an earning and once an hour the extension re-seals the profile and POSTs {"code", "sealedAt", "keys"} to it. What arrives there is already encrypted, so the host stores something it cannot read. server/vault-sync.mjs in this repository is that relay.

Optional, and sent only to the address above. It is kept on this device like every other credential and left out of the sealed code.

Put it back on a new device

Paste the code you saved — the whole file is fine, the code inside it is found either way.

Restoring replaces what this profile holds with what the code holds, and signs this device out so the next sign-in uses the restored account. Nothing is written until the code opens.

Security

Anyone who installs this extension can read its code, so it is built so that reading it gains nothing: no keys live inside it, and nothing it stores hands over an account.

  • No secrets in the code. Every credential is one you entered. It stays in this browser profile and travels only to the host you named.
  • Encrypted endpoints only. Checking…
  • Commands come from this extension only. A page or another extension cannot drive the worker, and what a page can influence stops at the ad slots it hid.
  • No password is stored. Only a salted PBKDF2-SHA-256 hash at 210,000 rounds — and five wrong tries pause sign-in.
  • No pictures are kept. A camera frame is measured and then dropped; only the verdict and its time are saved.

Sponsored offers

Shoppers can earn a small amount for visiting an advertiser, paid into the same cashback wallet. Point this at a sponsor or ad programme you are entitled to use: the extension shows only the offers it returns and records only the amount it books for a visit. Incentivising clicks on ordinary display ads breaks most ad networks' terms — use a programme that pays for these visits itself.

GET returns the offers; POST with {"offerId": "…"} books a visit. See the README for both shapes. Blank hides the Earn extra block.

Face age check

Works with nothing set up: the panel measures two frames on this device, keeps the verdict and never sends a picture anywhere. A relay is optional — only worth it if you want a provider-backed age estimate instead. Its credentials then live on that relay, never in this extension, and the panel gets back only a verdict. Leave both fields blank to use the on-device check.

POST with {"image": "data:image/jpeg;base64,…"} answers {"verdict": "over" | "under" | "unclear", "estimate", "provider", "reference"}. server/age-verify.mjs in this repository is that relay — Hugging Face (free tier) and Azure AI Face (F0 free tier) are both wired up. Only the verdict, the provider name, its reference and the time are stored.

Optional. Authenticates the extension to your relay only; the face provider's credentials stay on the relay. Use https:// unless the relay is on your own machine.
